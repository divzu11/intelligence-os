# Intelligence OS — Video Walkthrough Script

A ~3–4 minute screen-recording guide. Run the app in demo mode first
(`cd client && npm run dev`, then open the local URL). No setup, accounts, or
keys required — the app is fully populated with sample data.

> Tip: record at 1280×800 or larger. Resize the browser to a desktop width so the
> left sidebar shows (below ~768px it switches to a mobile bottom-nav layout — you
> can show that briefly at the end if you want to highlight responsiveness).

---

## 0. Intro (~20s)

> "This is Intelligence OS — a personal intelligence platform that monitors
> healthcare news, uses Claude to turn raw articles into operator- and
> investor-ready briefings, detects emerging trends, and writes a weekly memo.
> I'll walk through the five core surfaces."

Mention the stack in one line: React + Vite frontend, Node/Express backend,
Supabase (Postgres) for storage, Claude for summarization and analysis. Note
that you're running in demo mode with sample data so it's reproducible.

## 1. The Reader — Home (~50s)

Land on the home page (the Inshorts-style reader).

- Point out the **story card**: source, section color stripe, geography flag,
  and time-ago.
- Read the **AI summary** — note it's ~100 words, written for a busy reader.
- Expand the **Operator Take** and **Investor Take** — the same story framed for
  two different audiences. This is the core value prop.
- Use the **filter pills** (All / Healthtech / Investing / Operations / Insurance)
  to filter the feed.
- Navigate with the **arrow keys** (or the prev/next controls) to swipe through a
  few stories. Mention swipe works on mobile/touch.

> "Each article is summarized once and cached. The operator and investor takes are
> what make this more than a news reader — it's pre-digested intelligence."

## 2. Trend Radar (~40s)

Go to **Trends** in the sidebar.

- Explain the concept: the system tags every article by topic, then compares this
  week's volume to last week's to compute a **velocity** and a **status** —
  Emerging, Rising, Peaked, or Fading.
- Point to a **Rising** trend (e.g. "Generative AI") vs. a **Fading** one
  (e.g. "Medicare Advantage").
- Click a trend to **view its underlying stories**.

> "This is how you catch a signal early — not just what's in the news, but what's
> accelerating."

## 3. Knowledge Archive (~40s)

Go to **Archive**.

- Show **search / filtering** by keyword, section, and geography over the full
  history of ingested articles.
- Then demo **Ask the Archive** — type a question like
  *"What's happening with GLP-1 and payers?"* and show the synthesized answer.

> "The archive turns the feed into a queryable knowledge base. Ask a question and
> Claude answers over everything you've ingested." (In demo mode this returns a
> representative answer; with a live API key it's generated by Claude over your
> real archive.)

## 4. Weekly Memo (~40s)

Go to **Memo**.

- Walk through the four sections: **This Week in Brief**, **Top 3 Signals**,
  **Weak Signal to Watch**, and **US to India Watch**.
- Show the **archive of past memos** in the side list and open an older one.

> "Every week the system writes this memo automatically from the week's articles
> and trends — the thing you'd actually forward to a colleague or an investor."

## 5. Sources (~30s)

Go to **Sources**.

- Show the list of RSS sources with **section, geography, and health score**.
- **Toggle** a source on/off, and show the **Add Source** form.
- Mention the vertical is swappable: change the sources + prompts and the same
  system works for any industry, not just healthcare.

## 6. Close (~20s)

- (Optional) Narrow the window to show the **responsive mobile layout** with the
  bottom nav.
- Recap the architecture in one sentence: scheduled RSS ingest → Claude
  summarization + tagging → trend analysis → weekly memo, all served through a
  React reader.

> "That's Intelligence OS — automated, AI-synthesized intelligence for a single
> vertical, in a format you'd actually read every day."

## Pre-record checklist

- [ ] `cd client && npm run dev` is running, app loads with data visible
- [ ] Browser zoom at 100%, window wide enough to show the sidebar
- [ ] Close unrelated tabs / hide bookmarks bar for a clean frame
- [ ] Decide on narration vs. captions; do one dry run before recording
- [ ] Keep each section tight — aim for 3–4 minutes total
